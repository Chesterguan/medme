## 主线:OCR「诊断及建议内容空」的真因是检测阶段降采样

用户真机反馈:两张小程序存的高截图(超声、MR),**section 标题识别了、正文整段空**。诊断非猜——查 `oar-ocr-core-0.7.4` 的 `TextDetectionConfig`:PP 检测模型默认 `limit_side_len=960, limit_type=Max`,**不管原图多大先把长边压到 960px**。高截图(长边 2000+)被压到 0.375×,密集小字掉到检测分辨率以下 → 整段不进识别;标题字大幸存。**不是 rectify、不是认错字,是检测采样不足。**

**修法:纵向切片(banding),不换引擎、不动 rec、不碰 vault、不动模型。**`packages/ocr` 识别时按 `TILE_CORE_H=1100`(overlap 120)把高图切带,每带近原生分辨率单独 `predict`,按「核心区归属」(行中心 y 落哪带核心区就归谁,核心区首尾相接无缝无叠)去重合并回整图坐标。下游 `recognize_engine` / `recognize_engine_layout` 拿到的仍是整图坐标行,零改动。图不够高(≤1100px)走单次识别 = 逐字节等价旧行为,桌面/CLI 零回归。

**桌面实测**(960×2560,真实血常规报告堆 2 份,复现 0.375× 压缩):单次整图检出 **126** 行 → 切片 **199** 行,**+58%**。`band_owns` 去重规则纯逻辑单测 + ocr 24 测全绿。commit `04a602f`,叠在 build 36 之上(不回退 EXIF/代拍/rectify)。

## build 37 真机验收:检测漏段修好了,但暴露识别精度天花板

用户验收:「感觉好了那么一点点 但依旧不完美」。逐屏对比:

- ✅ **切片成功**:MR「诊断及建议」build 36 正文全空 → build 37 **1./2./7. 条目、报告/审核医师、地址全出来**。检测漏段闭环。
- ❌ **认错字(主要「乱」)**:数字截图字本清晰,但 mobile rec 模型出**形近字混淆**——岛**叶**→岛**吐**、**呈**→**吴**、**中线**→**审线**、乙状**窦**→乙状**卖**、**颞骨**→**颜骨**、**考虑**→**考愿**、**内**-中膜→**丙**-中膜;MR 第 3~6 条塌成「题缩 6岩@」乱码。这是 **PP-OCRv5 mobile(精简)rec 模型的精度天花板**,切片管找到字、管不了认对字。
- ❌ **超声提示「空」**:内容其实没全丢(「双侧颈动脉内-中膜不均增厚伴斑块」出来了),是被挂到误识别的「床意超声报告」行下 + 该行认错字,属版面归组 + rec 错叠加。

**下一步杠杆(未做,待定)**:换 PP-OCRv5 **server rec 模型**(精度高、体积约 mobile 5×,16.5MB→~85MB)。按 [ADR 计划](../../.claude/plans),这是「检测修好后、认字仍不准才评估」的那一步——现已到该阈值。**但必须先拿用户那两张原图桌面实测 server 模型的逐字增益 + 体积代价,再决定,不靠 TestFlight 猜**(用户已明确测试疲劳)。用户拍板本轮**先 park OCR**(「先这样吧」)。

## 医生代拍确认流(feat/doctor-mode-v2,Dart 共享 = 安卓自带 UI)

首启「你是?」模式选择器(我管自己/家人 vs 我是医生帮病人建档)→ 代拍走**用完即焚**内存态(`vault_ephemeral.rs`,`static EPHEMERAL` 平行于 `VAULT`,零共享代码避免 build-30 vault.rs 重构致 OCR 回归的坑)。流程:采集(拍/相册/文件多源累加)→ 批量 OCR → **待确认列表** → 点进单份看原件+识别 → **「确认这一份」(整份,非逐项**——用户:「整份即可,逐项太累说明产品失败」)→ 仅确认的进 summary → 未确认原件仍随包发、标「待确认」→ 即焚。全 UI 在 `lib/screens/doctor/*`,Dart 共享,安卓从本分支构建即自带。

## 决策/教训

- **按功能组织,不按分支切碎**(用户拍板,已存 memory `organize-by-feature-not-branch`)。EXIF 修复只在 v2、main 没有,差点把切片叠错基线丢掉 EXIF。每个 build = 上个 working build + 新修复,出包前查目标分支没回退。
- 安卓 OCR 现状分叉:`feat/doctor-mode-v2` 安卓走 ML Kit;`feat/android-pp-ocr`(基于旧 main,无代拍/切片)把安卓接 PP + 打包 `libc++_shared.so` 修真机崩溃。要让安卓 OCR 对齐 iOS(PP+切片),需把二者合流——本轮待定。
