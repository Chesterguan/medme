# 2026-08-14 行对齐尝试 —— 诊断存档,实现已撤回,实测倒退

**结论先行:这条实现在 683 份真实数据上让产品倒退,已被否决,不合并。** 本文档存档诊断过程、两次失败的算法尝试、以及一个在否决之后才发现的独立 bug——留给以后任何人重走这条路时省时间。

## 任务

`rebuild_layout_text`(`packages/ocr/src/lib.rs`)把 OCR 检测框拼成「视觉行」文本后,下游 `parser::extract_labs` 就在一维文本上用正则猜字段归属,不再知道每个 token 来自哪一列。目标:利用检测框还留着的 `left/top/right/bottom` 坐标,在行拼接阶段把「项目名列相对结果列逐行下移,到底部累积近一整行」这类版面错位修好。

## 一、错位形态实测(金标集 + 大盘,`MEDREP_DUMP_MIS=1` 抓取)

| 形态 | 任务给定占比 | 实测例子(`原文` 字段,来自真实 OCR 输出) |
|---|---|---|
| 英文缩写 + **另一项**的中文名 | 22% | `RBC　　血红蛋白`、`NEUT#　淋巴细胞数目`、`BASO#　红细胞计数`、`HCT　平均红细胞容积` |
| **行序号**被吃进这一行 | 20% | `3　INR`(真值 1.03,我们报 89)、`4567　PT%　PT活动度(PT%)　部分凝血酶原时间（APTT）` |
| 一行里两个中文项目名 | 8% | `乙肝E抗体　　Anti-HBc`(应为两个独立项目)、`肝表面抗体　乙肝核心抗体` |

三种形态全部复现,与任务描述完全吻合。根因在 `rebuild_layout_text` 的 step 1:按 `top` 就近归行,用固定容差(`0.6 * 行高`)判断两个检测框是不是同一视觉行。纸面弯曲导致项目名列相对结果/参考区间列逐行下移,累积到底部接近一整行高,固定容差的就近归行必然整栏错位一行。

**独立佐证**(标注员在人工看原图标注金标集时自发观察到,他们不知道有人在查这个):
> 「纸面弯曲导致项目名列相对结果列逐行下移,到底部累积偏移接近一整行高。按 y 坐标就近配对会整栏错位一行。」

## 二、试过的两条算法路线,为什么都失败

### 路线 A:全局最小代价 DP(按列聚类后,跨列做编辑距离对齐)

思路:把检测框按 **左边缘聚类**(不是整框区间聚类——长项目名的右边缘变化很大,会把区间聚类拖进相邻列,`find_dual_column_band` 的旧实现已经因为这个原因废弃过一次,详见该函数文档)划成若干「列」,列内按 `top` 排序即为该列自己的阅读序,**列内顺序不受纸面弯曲影响**(检测器不会把同一列的框读乱序,哪怕整体 y 偏移很大)。于是用一个 DP 把每一列对齐到框数最多的「主干列」,代价是 `top` 差值,跳过（缺失匹配）付一个固定代价。

**失败**:合成测试(20 行、行距 50px、项目名列漂移线性增长到 0.85×行距)显示,一旦漂移持续超过「半个行距」这条线,DP 会发现「把这一行开始的所有后续行都错位挪一行」在总 `top` 差之和上反而更便宜——因为 `pitch - drift` 在 `drift > 0.5*pitch` 之后比 `drift` 本身还小。DP 会**悄悄地、confidently 把整个表尾部错位一行**,而不是老老实实弃权。这正是 `rebuild_layout_text_report1_tilt_does_not_misattribute_reference_ranges` 那条测试文档里记录的同一个死结的另一种表现形式:漂移接近半个行距时,**任何基于 `top` 距离的全局代价最小化都无法安全判断**,因为「挪一行」在数学上真的更便宜。

试过加一个「离对角线 `|i-j|` 越远惩罚越大」的正则项去抑制这种级联,调大到 `skip_cost * 3` 才把 20 行中的级联错误从 8 行压到 1 行——但这只是把「DP 会作弊」的症状往后推,没有解决问题本身,而且这个正则项在**真实缺项**场景(列里本来就缺几格,不是漂移)会误伤:零漂移、纯缺项的合成测试下,加正则项后正确率从 17/17 掉到 3/17,因为一次真实缺项之后 `i≠j` 就会永久保持,正则项把这个**本该免费**的、已经被一次真实的「跳过」代价买单过的状态又重复扣分,导致 DP 宁可继续弃权也不愿意接受本来正确的对齐。**两个目标(容忍真实缺项、拒绝级联误配)在同一个代价函数里互相打架,调不出两全的参数。**

### 路线 B:保序贪心 + 置信度弃权(最终提交、后被否决的版本)

放弃全局最优,改成局部贪心两指针合并:每一步只比较「当前」这一对候选,`top` 差 ≤ 半个行距就配对;超过就看「挪到下一格」是否是**决定性地**更好(代价 ≤ 0.3×半行距的置信门槛),是则判定为真实缺项、跳过较靠后的一侧;两边都不够置信,判定为**真正模糊**,两边都弃权(各自单独成行),不去猜。

合成测试上这条线表现好:漂移测试 20 行里 19 行配对正确,剩下 1 行(漂移达 0.85×行距,已经逼近理论上限)干净弃权,不产生错误配对;缺项测试 17/17 全对,不误伤真实缺项。**12 个既有单测(含唯一那份真实倾斜版面 pin 测试)全部通过,0 回归。**

**但在真实语料上大幅倒退**(见下节)——协调者用同一二进制、同一评测口径对照 `out_ALL`(改前)与 `out_align`(改后)683 份实测:

| | 改前(out_ALL) | 改后(out_align) | Δ |
|---|---|---|---|
| 金标召回 | 68.4% (147/215) | 56.3% (121/215) | **−12.1pp** |
| 金标精度 | 79.9% (147/184) | 78.2% (122/156) | −1.7pp |
| 指标对、数值错 | 13.6% | 16.7% | 恶化 |
| 大盘错配率 | 12.6% (204/1623) | 14.6% (173/1181) | **+2.0pp,破红线** |
| 端到端 | 28.0% (1419/5068) | 19.9% (1006/5068) | **−8.1pp,破红线** |
| **产出总行数** | **1623** | **1181** | **−27%** |

三条红线全破。**产出总行数 1623→1181 掉了 27%** 是最能说明问题的一个数——这不是「弃权多了几条模糊行」能解释的量级,指向的是**大范围的整份破坏**,而不是零星的置信度判断失误。协调者最初的判断是「置信度弃权触发得太狠」,合理但不完整——下面这条是被否决之后才补上的另一半原因。

## 三、否决之后才发现的独立 bug(未及重新全量验证,如实记录)

对照 `out_align`(改后)里被拆得面目全非的文档逐份看原文,发现**至少一部分**倒退和「路线 B 的置信度弃权」完全无关,是实现上一个独立的范围计算错误:

`realign_table_rows` 判断「表格的纵向范围」时,用的是**整个页面**里所有 step 1 已经归成多框行的行的 `top` 最小值/最大值——而真实报告的**人口学信息头**(`姓名：科室：样本类型：`)和**页脚签名块**(`审核者：检验者：`)本身也经常是多框行,通常一个在页面最上、一个在页面最下,于是这个范围**经常覆盖整个页面**。结果是页眉、页脚里跟真实化验表毫无关系的框,全部被塞进列检测和跨列对齐,而这套机制是照着「干净表格」的几何特征调的,喂进去无关内容后产出的是垃圾——真实文档整份被拆成一格一行。

**修复验证**(683 份里的一份凝血四项报告,8 行,同一份文档改 bug 前后对照):

```diff
- 项目
- 结果
- 宿写
- 参考区间
- 秒
- 19.40
- *PT          凝血酶原时间                              ↑                   9.4--12.5
- PTA          凝血酶原时间活动度                               %               80--160
- 47                                               ↓
+ 宿写           项目                        结果                            参考区间
+ *PT          凝血酶原时间                    19.40     ↑   秒               9.4--12.5
+ PTA          凝血酶原时间活动度                 47        ↓   %               80--160
+ INR         凝血酶原标准化比值                  1.7       ↑                   0.8--1.2
+ *APTT        活化部分凝血活酶时间                40.2      ↑   秒               21--37
+ *Fib        纤维蛋白原含量                    5.80      1   g/L             2--4
+ *TT         凝血酶凝结时间                    20.2      1   秒               13.5--19.5
+ *DD         D-二聚体                      254       ↑    μg/L (DDU)     0--252
```

改前这份文档 8 个化验项**一个都读不出来**(每格独立成行,`parser::extract_labs` 的 `name value rest` 正则完全匹配不上);改后 8 项全部正确重建成一行一条记录。

**修复思路**(在 60~80 份小样本上验证,未跑满 683 份就被叫停,所以下面是"看起来对"而非"证明对"):

1. **只取连续的多框行区块**,不取全页范围——允许区块内出现至多 1 行「整行一起被拆散」的孤立单框行(容忍一次整行 OCR 漏检),超过就判定已经离开表格。这样人口学头和签名块(通常跟真表格之间隔着好几行无关内容)天然被排除在列检测之外。
2. 光有「连续」不够——**同一份文档里,一个化验项单独印成 2~3 行「标签 值」堆叠**(比如抗核抗体报告的 `名称/核型/滴度` 三行)在几何上和一张 3 行小表**完全无法区分**,连续性检查会把它当成表格误伤。补了两条门槛:区块至少 8 行(远高于原来判断「是否巧合」用的 4 行下限,一次性巧合和一张真正的重复结构表在规模上通常差得多)、且区块内多数行(≥60%)的框数要和众数一致(真表格每行框数稳定,这种「标签值」堆叠块每行框数彼此不一致)。

这两条门槛加上之后,原来两份完全被拆散的小文档(单项 ANA 抗核抗体、单项维生素 D)不再触发这套机制(区块行数 <8,门槛拦住),保持和 step 1 一样的旧行为;凝血四项那份 8 行的文档则被机制正确接管、修复。12 个既有单测 + 之前的 3 个回归测试全部保持通过,又补了一条 `rebuild_layout_text_realignment_does_not_pull_in_header_and_footer_rows` 单测把这个 bug 的复现场景钉死。

**没做的事,如实说**:发现这个 bug、验证修复思路的时候已经收到叫停指令,**没有把这版修复过的代码跑满 683 份重新计分**。所以不能声称"路线 B 加上这个修复就翻盘了"——只能说:被否决的那一版数字(倒退 12.1pp / 8.1pp)里,有一部分(具体多少不知道,凭手工抽查感觉不小)可能来自这个和「保序贪心弃权」设计本身无关的独立实现错误,而不是「保序贪心弃权」这个思路天生就该翻车。**这两件事在最终否决前没有被分开测量过,是这次交付的一个缺口。**

## 四、为什么判断这条路(纯几何)大概率没有安全区

抛开上面那个 bug 单独看,路线 A 和路线 B 的合成测试都指向同一个数学事实:**一旦某一列相对另一列的纵向漂移持续超过半个行距,仅凭两个检测框各自的 `top` 坐标,原理上就无法确定这一格该配到哪一行**——往前一行、往后一行,从几何上看是同样合理的假设,disambiguating 需要的信息不在坐标里。

- 全局最优会被这种模糊性诱导去做一次「一次性买单、后面持续省钱」的错误决策,静默级联。
- 局部贪心加置信度门槛能避免级联,但代价是**弃权**——而真实照片上落入这个模糊区间的比例,远比合成测试里假设的高(标注员反馈「累积偏移接近一整行高」是常态不是个例),弃权太多直接拖垮召回,松开阈值又直接拖垮错配率,两头都不讨好,这也是协调者独立复核出的结论。

**这不是调参能救的**——是几何信息本身在这个区间不够用了。

## 五、如果以后有人想再走这条路,建议方向

1. **先把本文档「三」里的 bug 修复用干净的 PR 单独提出来验证**(和"跨列几何对齐"完全正交,是纯粹的"划定表格范围"层面的 bug,风险低很多),看它自己在 683 份上的独立收益——这是本次交付遗留的、价值最明确的一个后续动作。
2. **对齐决策不能只看几何**。任务原始诊断里提到的「参考区间列形态独特,可以当锚点」「行序号列可以整列识别丢掉」都是内容信号,`find_dual_column_band` 已经用 `looks_like_measurement` 证明了内容信号在这个文件里是可行、已验证过的路子。真正过半行距的模糊区,需要靠内容(这格像不像数值/范围/单位、参考区间的独特形态)而不是几何本身去判断该往前配还是往后配——这条路没试,是本次没有余量做的下一步。
3. 无论用哪条路线,**必须先在真实语料的一个中等样本(如 60~100 份)上人工逐份比对改前改后的产出文本**,而不是只信合成单测——本次两个严重 bug(DP 级联、页眉页脚全页污染)都是合成测试完全测不出来、真实语料一眼就能看见的。
