# schema 2(族级 facts)回归门:MedRepBench 682 份同轮实测(2026-09-17)

schema 2 的 prompt 在 v1 逐字基础上多要一组族级 `facts`。**多问一件事会不会把化验表
抽差了** —— 这是本轮唯一要回答的问题。结论:**没有,门通过**。

## 怎么跑的

同一批文档、同一次会话、同一套请求参数(`extract_params.json` 的 image 臂:
`max_tokens 8192` / `reasoning_effort low`)、同一个模型(`deepseek-flash`),
**只换 system prompt**(`extract_v1_system.txt` ↔ `extract_v2_system.txt`)。

```bash
export MEDREP_ROOT=<medrepbench>   # gt.tsv 由 medrep_make_gt.py 生成
export DEEPSEEK_API_KEY=$(tr -d '[:space:]' < ~/.deepseek_key)
medrep_llm --mode image --schema 1 --jobs 12 --out out_s12   # 可续跑,重复调用直到不再有失败
medrep_llm --mode image --schema 2 --jobs 12 --out out_s12
medrep_llm --reverify --schema 1 --out out_s12               # 离线重算,不碰网络
medrep_llm --reverify --schema 2 --out out_s12
medrep    --score --out out_s12
```

产出目录按 schema 分开(`deepseek-image` / `deepseek-image-s2`),所以两条臂写同一个
`--out` 也不互相覆盖,`score()` 把它们当**并排的两列**打出来 —— 同分母,直接可比。

**两条臂最后落在同一批 682 份上**(各自 `.txt` 的文件名集合逐份相同,差集为空):
683 份非空图里有 1 份(`b1678873265630271523.png`)在**两条臂上都**被 `max_tokens`
稳定截断(各重试 3 次),按生产同一条判据算失败、不产出。

影像提示、HPV/妊娠结论这类叙述块。真正要验 facts 抽取,得用病程语料(Task 14 的合成
SLE 语料),不是这里。

## 三条口径提醒

1. **稳定截断的那 1 份在两条臂上一起掉出分母**,所以它没有偏袒任何一方 —— 但也意味着
   「schema 2 在长文档上是不是更容易被 8192 截断」这个问题本轮**没有答案**:两条臂的
   失败集合恰好相同,样本量 1。真要量,得单独跑一轮更大的 `max_tokens`。
2. **`temperature: 0` 在这个端点上不是确定性的**(前一轮重跑同一条臂漂了约 0.4 点)。
   本轮三条指标的差都在 ±1.0 以内,**与这个漂移同量级** —— 结论只能是「没有可检出的
   退化」,不能是「schema 2 更好」。
3. `all_total` 这一轮起把 facts 算进分母了(`v.rejected`/`v.unverified` 本来就连 facts
   一起数)。schema 1 下 facts 恒空,老数字逐字不变。
