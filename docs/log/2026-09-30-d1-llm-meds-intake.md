# 2026-09-30 · D1:云抽取的 meds 接进解析链

**为什么**:模型早就回了 `meds`,`aggregate` 只读 `labs`;用药单还是正则,「片」那种换行事故(见 2026-09-28 log 与 `24aab6a`)模型本可避免。三视图 spec 的「现在」层要的是能推剂量变化的数据,正则给不了。

**做了什么**:`parser::meds_from_json`(每条拼成「药名 剂量 频次」一行复用 `extract_meds`,不另写正则);`aggregate` 有 JSON 且非空就用、否则退正则,不按 doc_type 过滤;`MedSpan.unverified`。facts 不加层——`Ctx::build` 早就在读 `deid::Fact`,spec §5 已改回现实。

**评测**:李静 15 份 × DeepSeek `deepseek-flash` schema 2,原始输出入库为 fixture(`packages/profile/testdata/extractions/`),测试跑 `deid::verify` 后逐条核(`profile/tests/llm_fixtures.rs`,9 过 1 ignore):
- 处方 6 味药剂量频次:全中(20mg qd / 0.75g bid / 0.2g bid;7.5mg qd / 0.5g bid / 0.2g qd)。
- 住院(含起止日)、肾活检、贝利尤单抗输注、激素与 MMF 两次减量、OCT/视野:全中。7 份化验单 meds 均为空。
- 召回缺口:眼科报告的「眼底」exam_done——模型抽到了,但 evidence 把原文跨行的一句拼成一行,verify 逐字规则丢掉。测试 `#[ignore]` 记名;修法在 verify(允许跨换行匹配)或 prompt,不在 D1。
- 顺带看到:模型在处方里把碳酸钙片也列进 meds(原文有),出院记录把甲泼尼龙冲击记成 infusion、NIH 活动指数记成 scale——都是原文有的,按「下界断言」不算错。

**独立审查抓出来的**(reviewer 用探针对基线实测,全部修完、各带回归测试):
- 接行修复有回归:不带冒号的标题行、散文行、裸药名行都「没有剂量」,会把下一味药粘上(「出院带药醋酸泼尼松片」)。加两道闸:上一段不是标题;下一行剂量前的名字自己解析不成药才接。
- 拼成一行再解析会把名字里的数字当剂量(碳酸钙D3片 → 「3 片」),改成名字/剂量/频次分开解析;留条件按原话算(模型写了剂量或频次原话就留,哪怕是浓度、哪怕词典没有)。
- 没剂量的提及(门诊「羟氯喹维持」)会冲掉处方上的剂量,规则改成不覆盖已有剂量。
- `MedSpan.unverified` 只在为真时进查看器 JSON 的 `unverified` 键,老形状不变;D3 界面按它标「需核对」。
- 只跑了两个 crate 漏了 pipeline 一条常量测试(假药「片」消失后 9 → 8)。教训:收尾跑 `cargo test --workspace`。

**PR 审查(#235,第二轮)又抓出 7 条,都修了**:接行只对「上一行是分隔符连写的清单」才接(散文/裸名行后面词典外的药不再被粘成假名);冒号只剥标题那一个,「药名:剂量」写法不再被切断;剂量规则对称(有日期的无剂量提及先到、无日期的处方后到,剂量也要进来);JSON 路径补上说明行守卫;fixture 测试只认 `.txt`;部署脚本按退出码判函数存在、读不到线上密钥就中止而不是悄悄重生成。

**留到 D3 的**:`ActiveMedDto` 还没有 `unverified` 字段,图片模式没核上的药在 App 用药列表里和核过的长一样(以前这类药根本进不来)。要动 FRB 生成的 Dart,和「需核对」标记一起在 D3 做。性能:`aggregate` 对每份文档的 extraction_json 解析两次(labs 一次、meds 一次),保险箱几十份文档量级下不显,D2 动 `Ctx` 时顺手改成解析一次。

**记下没修的**:模型用泛称当药名(「激素 10mg qd」与「泼尼松 7.5mg qd」并排像两种药),D2 做别名映射或改 prompt;fixture 测试只做下界断言,聚合层退化没盯,后面加。
