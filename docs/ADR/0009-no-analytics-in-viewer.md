# ADR 0009 · 医生查看器永不埋点

Status: Accepted · Date: 2026-07-29

## Context

App 侧接入了 PostHog 行为分析(只采行为骨架,不做持久 ID;清单见
[`docs/analytics-catalog.md`](../analytics-catalog.md))。接完之后一个自然的下一步是:
**查看器(hosted viewer)也埋一下吧?**

这个念头有很强的正当性,值得认真记下来它为什么被否决——否则半年后还会有人再提一次,
而且那次可能没人记得代价:

- 查看器是**医生真正读病历的地方**。「医生打开了没有、看了多久、翻没翻原件」
  是关于这个产品成不成立的**最重要的问题**,而 App 侧完全测不到。
- 技术上极其容易:一段 script 而已。
- 「只是个 page view」听起来无害。

## Decision

**查看器(`web/hosted-viewer/index.html` 及由它派生的自包含分享 HTML)不接入任何
分析、不发起任何非必要网络请求。这是红线,不是暂缓。**

两条独立的理由,任何一条单独成立就足够:

### 1. 查看器的 DOM 里躺着**已解密的病历原文**

这不是「可能泄漏内容」,是「内容就在页面里」。任何分析脚本都运行在同一个文档中,
拿得到全部明文。这与 App 侧完全不同 —— App 侧的埋点代码够不到病历,只能拿到我们
显式传给它的分桶值。

而分析 SDK 的自动采集(autocapture、录屏、点击文本)恰恰以「抓取页面内容」为设计目标。

### 2. 它要求打开 CSP 上最强的那道约束

查看器的 CSP 里 `connect-src` 只放行**认领密文所在的那一个源**;
`packages/share/src/share.rs` 在组装**自包含分享**时,会把它收回
`connect-src 'none'`(`share.rs:474`),并有测试守着(`share.rs:524`)。

这条性质的含义是:**离线分享的 HTML 在技术上无法把任何东西发到任何地方。**
不是「我们承诺不发」,是发不出去 —— 这是我们对病人能给出的最强的一句话。

埋点要求把 `connect-src` 打开。**一旦打开,那句话就永远说不了了。**

## Consequences

**放弃的:**

- 医生的阅读行为**永远测不到** —— 打开率、停留时长、有没有翻原件、在哪一屏放弃。
- 「二维码被扫了几次」测不到(扫码发生在浏览器,不在 App)。
  出码与认领的关联因此只能看**总量比**,不能逐条对上(见 catalog 第四节)。

**换来的:**

- 「密钥在 `#` 之后、从不上传」与「离线分享无法联网」这两句话,在代码层面是可验证的,
  而不是承诺。
- 查看器不需要任何隐私政策、不落任何 Cookie、不进任何双清单。

**替代手段(如果真的必须知道医生看没看):**

问医生。主动收集反馈,而不是在装着病历明文的页面里装探针。

## 落地约束

- `share.rs` 里收回 `connect-src 'none'` 的那段代码和它的测试**不得删除或放宽**。
- 若将来查看器确需新增一个网络来源(如换存储),只允许追加**取密文**所必需的源,
  并同步更新 `CLAIM_CONNECT_SRC` 常量与 CSP —— 两处必须一起改,`share.rs:30` 有注释提醒。
- 这条约束写进了 `docs/analytics-catalog.md` 第七节「明确不采的」,那份文档由
  `apps/mobile_flutter/test/analytics_catalog_test.dart` 校验,删掉会让测试红。
