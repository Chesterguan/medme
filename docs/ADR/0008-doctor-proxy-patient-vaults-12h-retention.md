# ADR 0008 · 医生代拍改用「每病人一个独立保险箱 + 12 小时本地保留」,取代即焚临时箱

Status: Accepted · Date: 2026-07-26 · **supersede 掉「代拍 = 单会话即焚箱(`vault_ephemeral`)」这一设定**(该模块保留但退居残留清理,见 Consequences)

## Context

代拍第一版(build 38 起)是**用完即焚**:同意 → 在系统临时目录开一个一次性 `vault_ephemeral` 箱 →
采集 → 交付加密文件 → 立刻整棵删掉。设计意图是「医生设备上不留别人的病历」,直觉上最安全。

真实诊室用下来,这个模型和医生的工作节奏对不上:

1. **医生不是当场写完病历的。** 门诊拍完通常要几小时内才把病历写完,期间要回头核对拍到的东西。
2. **交付是一次性的、且很脆。** 一旦交付完成箱子就没了;如果文件没成功交到病人手上(现场传输失败、
   病人手机没电、选错分享渠道),**没有第二次机会** —— 病人已经走了,材料也删了,只能请人重新来拍。
3. **一次门诊不止一个病人。** 单会话模型下没有「今天代拍过谁」这个概念,医生无从回看。

同时,`vault_ephemeral` 作为实现手段也有结构性代价:它是一份**与 `api::vault` 平行的副本**
(自己的 ingest / preview / share / 详情读取一整套),两边逻辑要同步维护;而且它把「已确认」状态
放在进程内存(`Mutex<HashMap>`),天然活不过 app 重启。

反过来,把「不留底」这个承诺放宽也不是没有边界的:告知书里已经明确写给病人看,口径必须一致
(见 [2026-07-25 log](../log/2026-07-25-NEXT-doctor-mode-12h-retention.md) 里改口径那一步)。

## Decision

**代拍的每个病人 = 一个独立保险箱,数据在医生本机最多保留 12 小时,到点自动删。**

- **每病人一个 vault,走与患者模式完全相同的链路。** 病人目录 `<support>/proxy-patients/<id>/`,
  其下 `vault/`(真相 + 派生库)与 `data/`(该病人**自己的一次性 device id**,不带医生设备身份;
  那里没有 `icloud_enabled` 标记,所以别人的病历永远不进医生的 iCloud)。开箱用现成的
  `openVault`,采集用现成的 `ingestImageWithText`/`ingestBytes` —— **不再维护第二套 ingest/share 逻辑**,
  「姓名不匹配」提示也因此白捡。
- **12 小时 TTL 由 `ProxyPatientManager` 在加载时执行**(进医生主页/开始代拍都会走到),超时连目录一起删。
  不用后台定时器:app 不在前台时本来也不该跑定时器。落在 `<applicationSupport>` 而非系统临时目录 ——
  临时目录系统随时可清,撑不住 12 小时的承诺。
- **交付后不删。** 病人留在「今日病历表」,12 小时内可回来补拍、重新核对、**重新交付**。另有单个删除与「清空」。
- **命名空间与患者模式完全隔离**:代拍病人表在 `<support>/proxy_patients.json`,与 `profiles.json` 互不可见;
  患者模式的 `ProfileManager` 与保险箱格式**一个字不动**(硬约束)。
- **确认状态 / 拍前同意 / 姓名不匹配 落在 Dart 侧按病人持久化,不进 Rust、不进保险箱。**
  它们要跨 12 小时窗口和 app 重启存活,而**往保险箱里加事件类型 = 动格式**,会破坏与桌面的逐字节兼容。
  交付时把 `confirmedIds` 作为参数传给 Rust。
- **新增两个 Rust 函数而不是改动既有的**:`create_proxy_share(expires_days, consent, confirmed_ids)` 与
  `proxy_summary(confirmed_ids)`。原因:普通 vault 的 `create_share` 不收 consent/confirmed_ids,
  带同意的版本此前**只存在于 ephemeral 那条路**;新增是纯加法,患者模式那条路零风险。
  两者底下与原 ephemeral 版调**同一个** `build_encrypted_share_with_consent_and_confirmed`,产出格式同构。
- **「进程级 vault 被顶掉」用机制解决,不用调用约定。** Rust 的 vault 是进程级单例,开代拍病人的箱子会顶掉
  医生自己的档案,而各调用点 `await` 的先后**不保证** FFI 到达顺序。三层:
  (1) 所有开箱排一条 **FIFO 队列**,先发出先生效;(2) 新增 `current_vault_root()` 能问「此刻开着哪个箱子」;
  (3) 每次落库/交付前 `ensureProxyVaultOpen` **硬校验**,不对就重开,重开还不对就**中止写入并报错**。
  宁可这次采集失败,也绝不把病人的材料写进医生自己的档案。
- **12 小时这个数字与告知书绑定。** 同意屏、顶部横幅、主页说明、交付对话框四处口径必须一致;
  任何一处写「不留底」都是对病人的假承诺(本次就修掉了交付对话框里残留的那句)。

**本次不做异步上传微服务器**,连 TODO hook 都不留(没有调用方的 hook 是死代码)。

## Consequences

- (+) 医生可以在 12 小时内回来补拍、核对、**重发** —— 交付不再是一次性的,现场传输失败不再等于材料丢失。
- (+) 「今日病历表」按病人名列,一次门诊多个病人有了归属。
- (+) 删掉了维护第二套 ingest/preview/share 逻辑的负担;姓名不匹配提示、普通导入的所有改进自动惠及代拍。
- (+) 「不误写医生自己档案」从注释约定升级成每次写入前实际比对过的事实,可验证、可失败。
- (−) **医生设备上确实会留别人的病历,最长 12 小时** —— 这是拿「不留底」换「能重发 + 能写完病历」。
  代价靠三件事兜:告知书明写并当面签字、到点自动删、随时可手动「清空」。设备丢失/被查看的窗口从 0 变成 12 小时,
  这是本 ADR 最实质的取舍,不是实现细节。
- (−) 病人数据落在应用支持目录而非临时目录,系统低存储时不会替我们清 —— TTL 必须自己可靠执行
  (故 `ensureLoaded` 顺带清孤儿目录,防崩溃残留)。
- (−) `vault_ephemeral` 模块保留但已无产品调用方,只剩启动时的 `EphemeralSession.sweep()` 负责清理**旧版本**
  残留在临时目录里的即焚会话(升级路径的一部分)。等旧版本用户面足够小后可整体删除。
- **未变**:患者模式 `ProfileManager` / `vault.rs` 存储格式 / 与桌面的逐字节兼容不变;
  纯端上、云只密文的原则不变([0003](0003-content-addressable-storage.md) / [0007](0007-android-doc-scan-degms-and-geometry.md));
  拍前同意仍进加密包。
