## 描述(App Store Description)

```
换一家医院,医生问「以前怎么治的」,翻出一叠化验单——这是 MedMe 想解决的事。

拍下化验单、处方、出院记录,MedMe 在你手机上自动认字、按每次就诊排好队,能看清
化验值怎么变化。看病时,过敏、在治、在吃、最近的数,一页递给医生就够。

・「病历」「趋势」「我」三个入口,首页一颗按钮直接给医生看
・化验值按时间排成趋势,一眼看出在往好还是往坏走
・当面出示二维码给医生看,或者请医生用「代拍」直接把这次的病历建进你的档案——
  代拍生成一个取件码,医生手机上的材料 12 小时后自动清除
・为每个成员分别保存,各自独立、不会混在一起
・换手机可以用口令、恢复码,或者用已经登录的另一台手机扫码批准找回

关于你的数据

账号是可选的。不登录也能用,病历就在这台手机里——只是换手机找不回来。

登录之后,云端备份默认打开:每个成员的病历在你手机上加密之后才上传,我们那边
只有密文,没有解密密钥,打不开。这个开关随时可以按成员关掉。

第一次添加病历时,我们会问你一次要不要开「云端整理」:开了,病历画面会先在你的
手机上把姓名、证件号、手机号、病历号、医院名涂掉,再送到中国境内的云端模型去
认字,把化验值、诊断、用药整理成表。不开也能用,只靠这台手机认字。这个开关以后
在「我 → 云端」里随时可以改。

文字识别、查看、导出都不需要联网。

隐私政策:https://medmenow.com/privacy.html
用户协议:https://medmenow.com/terms.html

重要提示

MedMe 是个人病历整理工具,不是医疗器械,不提供诊断或治疗建议;一切以原始医疗
文件为准,请遵医嘱。文字识别可能出错——请把识别结果当作草稿,重要信息务必对照
原件核实。

MedMe 以 AGPL-3.0 开源,代码公开可查:https://github.com/Chesterguan/medme
```

## App 隐私(Apple「隐私」问卷)参考

⚠️ **这一节是提交前核对用的参考起点,不是最终问卷答案。** 与
`docs/app-store-submission.md` 第四节(2026-07-30 已填、已提交)相比,**账号 /
云端备份 / 云端整理这一整套是那之后才加的**,不能整段照抄旧结论——尤其是
「Health 不勾」那条,下面单独说明为什么现在必须重新判断。

### 沿用不变的部分

| 项 | 答案 | 依据 |
|---|---|---|
| 使用数据(Usage Data → Product Interaction) | 收集,仅用于 **Analytics**(不勾 App Functionality) | 关掉统计后 App 一切照常;`distinct_id` 每次启动由 `Posthog().reset()` 重置(`lib/analytics.dart:182`),不采 IP/地理位置(privacy.html 「我们刻意不做的」一节) |
| 与身份关联 | 否 | 同上,无跨启动标识 |

### 账号系统带来的新情况(需要重新判断,旧文件没有这几项)

| 项 | 答案 | 依据 |
|---|---|---|
| 联系方式 → 电话号码 | 收集(登录与按手机号加成员用) | 服务端只存 HMAC 哈希,不存明文号码——privacy.html:「登录会用到你的手机号,但我们不保存号码本身」;「三种授权」一节 |
| 与身份关联 | 是 | 哈希对应同一账号 |
| 标识符 → 设备 ID | 收集(账号下的设备管理、换机批准) | App 自建编号,非 IMEI/IDFA 等系统级标识符——privacy.html 「三之二」表格「设备记录」行 |
| 与身份关联 | 是 | 挂在账号下 |
| 用于追踪(以上两项) | 否 | 不与广告/第三方拼接 |

### ⚠️ 健康与健身(Health)——与旧文件结论不同,不能沿用「不勾」

旧文件「不勾 Health」的理由是**「我们从不具备访问能力,只有密文,解密密钥从不
发送到服务器」**(援引苹果对 Payment Info 的先例)。这个前提对下面两条至今仍然
成立,可以继续沿用旧理由:

- **出示二维码给医生看**(privacy.html 第三节第 3 项):服务器只存密文,密钥在
  链接 `#` 号之后,不上传。
- **代拍**(第三节第 4 项):同一条通道,同样只存密文。

但**云端结构化整理**(第三节第 7 项)是旧文件写成之后才上线的功能,不满足
「我们从不具备访问能力」这个前提:发给我们自己转发接口、再转给 DeepSeek 的那张
涂黑图**不是密文**——「我们的服务器和 DeepSeek 都能看到它上面剩下的内容」
(privacy.html 开头段落;第三之三节表格「DeepSeek」行:「这不是密文,DeepSeek
读得懂上面剩下的内容」)。这已经是收集了可读的健康相关数据,按苹果的类别定义应该
勾 **Health**:

- 用途:**App Functionality**(结构化整理是产品功能本身,不是分析或广告)
- 与身份关联:**否**——发送前已脱敏,姓名、证件号、手机号、病历号、医院名等已经
  涂黑或替换(privacy.html「不含姓名、证件号、手机号、病历号、医院名」)
  ⚠️ **这个「否」尚待创始人/合规负责人拍板,不是最终答案**:上面的论证只覆盖了
  载荷内容已脱敏,没有把 `/v1/extract` 这条请求**本身经账号会话发出**这一点
  算进去(`lib/cloud_extract.dart:366` `ApiClient.background(session, ...)`——
  服务端处理这条请求时明确知道是哪个账号发来的,即使不落盘、不进日志)。苹果
  「Linked to You」问的通常是数据能否经收集过程与身份关联,不只是载荷内容
  干不干净。提交前不要直接照抄这里的「否」。
- 用于追踪:**否**
- 用户可控:默认关闭,第一次添加病历时明确询问、用户同意才开启,可在
  「我 → 云端 → 云端整理」随时关掉——如果问卷里有说明栏,把这句写上

⚠️ **这是整份参考里把握最低的一条,建议提交前找人再核一遍**,并对照
`ios/Runner/PrivacyInfo.xcprivacy` 是否已同步(旧文件第八节的检查项依然适用)。

### 用户内容(照片/文件)

原件照片、PDF 始终只存在本机,不经过我们的服务器——除非用户主动出示二维码、
被医生代拍、或云端整理送出脱敏图(以上均已在别处列出)。单就「原件本身」不再
另勾一项。

## 不写什么(医疗合规红线)

- 不写「诊断」「判断」「结论」一类词——MedMe 不做判断,首屏声明与「关于」页的
  免责声明原文都这样说(`first_run_consent.dart` 第一条声明、
  `settings_screen.dart:758`)。
- 不写「AI 医生」「诊断级」——已被松绑的旧口径,见 memory `landing-messaging-2026-07`。
- 不写「零服务器」——账号/云端备份/云端整理上线后这句已经不真,同一条 memory 的
  教训。
- 不写具体用户数/医院数/好评数——没有可核实的数字,不编。
