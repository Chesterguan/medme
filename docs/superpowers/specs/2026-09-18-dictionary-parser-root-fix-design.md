# 词典 / 解析层根本解法 — 设计稿(待用户审)

日期 2026-09-18 · 状态:草稿 · 触发:病程档案线挖出 WORKLIST A32 ①–⑨,逐条打补丁堵不完。

## 0. 结论先行
两类问题、两个根因、两个根本解法:
- **化验名字配错**(UPCR↔ACR、CH50↔CA50、/HP 归零)——根因:`terminology::resolve` 靠字符串相似度(`fuzzy_lookup` 0.4)兜底,不看单位、不看编码、不区分量纲。解法 **A:单位感知 + 编码化的词典**。
- **处方剂量读错**(规格压过用法、途径被吞、「钙片」拆成「片」)——根因:用正则从处方笺猜「用法」。解法 **B:用药信息由 schema 2 的事实抽取给出并本机逐字核对,正则只做没开云端整理时的兜底,且兜底宁缺毋错**。

两者都不改产品形态,不改隐私边界(送出去的仍是脱敏后的同一份内容)。

## A. 词典:单位感知 + 编码化(packages/terminology)
A1 **词条带量纲与单位族。** `Entry` 加 `unit_family: Vec<String>`(与 `UnitConversion` 表同源)和 `dimension`(如 `per_hpf` / `per_ul` / `ratio_mg_per_g`)。`resolve(name, unit)` 在给了印刷单位时,**单位不在候选词条的单位族里就不接受该候选**(不是降分,是拒绝);没给单位才允许旧行为。
A2 **短代码只走精确表。** 纯 ASCII、长度 ≤ 6 的查询(CH50、CA50、C3、ANA、ALT…)只按精确别名(大小写不敏感)命中,**永不模糊**;模糊匹配只对 CJK、长度 ≥ `FUZZY_MIN_LEN` 的名字开放。
A3 **同名不同量纲拆条。** 尿红细胞/白细胞按 LOINC 拆成 `/HPF`(13945-1)与 `/uL`(5808-1)两条,由印刷单位选条;UPCR(2890-2)与 UACR 各自独立别名集,跨「比值族」禁止模糊。
A4 **跨院参考区间随点走。** parser 的 `LabPoint` 保留该点自己的 `ref_low/ref_high`;序列层不再「取最新一张单子的区间」;趋势与病程档案的「偏高/偏低」按点自己的区间判。
A5 **评测闸。** 在 MedRepBench 评测(`packages/ocr/examples/medrep*.rs`,683 份)上加「解析混淆表」:一份已知易混对清单(A32 里的全部 + 评测里发现的),CI 要求混淆数为 0 且召回不退。任何改动阈值/别名的 PR 必须过这道闸。
A6 **批量校准:用云端模型一次把词典喂饱。** 从评测语料抽出全部不同的「化验名 + 印刷单位」组合(只有项目名和单位,无数值、无病人信息),**一个请求**送模型:系统提示给出 642 个规范键(键、中文名、LOINC、单位族)与规则(只在确定时映射、不确定写 unknown、不许发明键、原文逐字返回);返回 JSON。本机按 A1 规则核对(键存在、单位在族内、一对多冲突标出),与现有词典解析结果比对得出「混淆清单」;差异表**人审**后进词典成别名,并写进 A5 的评测闸。在线时由 schema 3 让模型在每行化验旁直接给规范键,词典只核对不猜;没开云端整理的用户只用词典,但词典已被校准、被闸看住。送出去的只有项目名和单位,不进隐私边界。约 1–2 天。

## B. 用药:事实抽取为主,正则兜底(packages/deid + parser)
B1 **schema 2 事实的用药字段补齐:** `route`(口服/静滴/皮下/外用…枚举)、`form`(片/注射液/乳膏…枚举)、`dose_per_admin`(数值+单位,原文逐字)、`frequency`(qd/bid/tid/qn/qod 枚举)、`start`/`stop`;**每日剂量不让模型算**,本机由 dose × frequency 得出。提示词仍是 v2 字节前缀 + 追加(与 v1→v2 同一做法,测试钉住)。
B2 **核对规则:** 数值与单位逐字子串核对(带数字边界),枚举字段按允许值表核(已有 `FieldKind::Enum` 机制),证据行必须逐字存在;核不过的字段置空,不猜。
B3 **聚合优先级:** 某文档有 schema 2 抽取结果时,`MedSpan` 的剂量/途径/剂型来自事实;没有(云端整理关着)才用正则。`latest_raw_name` 退休,换成显式 `latest_form` / `latest_route`。
B4 **正则兜底宁缺毋错:** 同一行同时有「规格」(`×N片`、`Ng×N`)和「用法」(`用法:`、`每日`、`每次`、口服/静滴)时取用法;分不清就 `dose = None`(进「换算不了」),绝不取规格;药名切分不允许以「片/胶囊/注射液」这类剂型词单独成名。
B5 **评测语料:** 从 MedRepBench 挑真实处方笺建「用法金标」;合成 SLE 语料补非泼尼松激素与多文档激素史;CI 闸:金标上每日剂量 0 错。

## C. 顺序与代价(估)
1. A2 + B4(最便宜、收益最大,各半天)——可作为内测后的第一个补丁。
2. A1 + A3 + A5 + A6(3–4 天;A6 的一次请求几毛钱)。
3. B1–B3 + B5(3–4 天,含提示词回归评测)。
4. A4(1–2 天,parser + 趋势/病程档案两端)。
全部在公测前合入;每步各自的评测闸就是验收。

## D. 不做什么
- 不换模型、不绑模型名(既定决定)。
- 不在服务端做解析(病历不出手机的边界不变)。
- 不追求正则「更聪明」——它只负责在没云端整理时别给错数。
