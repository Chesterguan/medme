## 已知盲区(对外话术不承诺 100%)

- 手写姓名 OCR 漏检、二维码里的病人 ID:靠图片档页眉页脚整带涂黑覆盖,文本档覆盖不到。
- 「未见」≠「没有」:语料几乎全是化验单;住院病案首页、门诊病历、影像报告的形态由 `discharge_1`/`outpatient_1`/`imaging_1` 补(自写,字段名取自真实住院首页/门诊单/影像报告惯用词,非真实语料抽样)。
- Task 2 审阅记录、**尚未修**的 7 个盲区,钉在 `tests/fixtures/known-gaps/`(`cargo test -p deid --test fixtures` 里的 `known_gaps_are_pinned_not_enforced` 会跑;`.expected.txt` 存的是现状,平时是绿的,只有这个现状**变了**才会失败——变红去核实是修好了(该升级成主 fixture)还是换了种漏法):
  - 电话号后面多粘一位数字,整段座机号连着多出来的那位一起漏(`landline_glued_extra_digit_1`)
  - 号码后面紧跟着一个孤立的 `%`,被误判成化验值单位,整段号码放行(`id_before_percent_unit_1`)
  - 号码后面没有空格直接接 `/L`,同样被当成化验单位放行(`id_glued_to_slash_l_unit_1`)
  - 化验值和它的单位中间隔了一个参考区间,不是紧邻的下一个词,整段值被当号码误杀(`lab_value_unit_not_next_token_1`)
  - 参考区间两侧有空格(`100000 - 300000`)时,判断"是不是区间"的邻接字符检查失效,两个数各自被误杀(`spaced_range_overmasked_1`)
  - 号码后面紧跟中文叙述但中间夹了「年」「第」这类字,取值在「年」处提前收尾,残留的号码尾巴(`第123号`)留在明文里(`admission_no_trailing_fragment_1`)
  - 人名锚点(审核者/检验者等)后面如果跟的是叙述句而不是姓名,6 字上限会把叙述句的前 6 个字整段当"姓名"吃掉,读起来更像误伤叙述而不是漏(`six_cjk_anchor_eats_narrative_1`)

## 怎么加一种形态

`tests/fixtures/<类别>_<n>.txt`(首行 `# known: 姓名|证件号或-|手机或-`)+ 同名 `.expected.txt`;跑 `cargo test -p deid --test fixtures`。
`.expected.txt` 不是把 `redact_text` 的输出直接存下来——先跑一遍,人工核对输出里已知身份真的不在了、且年龄/性别/科室/化验值/单位/参考区间原样保留,核对完再存。
已经确认还漏的形态放 `tests/fixtures/known-gaps/`,同样一对文件,`.expected.txt` 记录的是**当前**(有漏洞的)实际输出——不是期望修好后的样子;这对文件会被逐字节钉住,输出变了测试就红,不是"永远绿的报告"。
